# NoMess

> 任何你複製下來格式亂掉的內容，下次貼上時都已經自動變乾淨好看——在桌面（macOS 先做，Windows 之後），背景自動運作，不用手動跑工具。

- 網域：`nomess.noky.dev`
- 平台：macOS 優先，Windows 之後
- 定位：先自己用，驗證有用之後上架給所有人用

---

## 1. 問題

終端機（或其他來源）複製出來的內容貼到別處常常「亂」，常見亂源不是 ANSI 色碼本身被複製（大部分終端機複製時只拿純文字，不帶跳脫碼），而是：

1. **硬換行殘留**——終端機依視窗寬度自動換行，這些視覺換行被當成真正的 `\n` 複製出去，貼到會自動 reflow 的地方變成一堆斷斷續續的短行
2. **固定寬度排版失真**——終端機靠空白對齊的表格/樹狀結構，貼到非等寬字型的地方全部走位
3. **CLI 介面符號夾帶**——像 Claude Code 這類 TUI 工具的 `⏺`、`⎿` 等介面標記符號，複製時被當內容一起帶走

## 2. 競品 / 既有方案（做決策前查過的）

| 產品 | 做什麼 | 跟 NoMess 的差異 |
|---|---|---|
| [Claude Code Paste Cleaner](https://trevorfox.com/2026/07/clean-up-claude-code-copy-paste/) | 網頁工具，手動貼上清理終端機/Claude Code 輸出，有純文字模式與 Markdown 模式 | 清理邏輯正確，但**手動流程**（複製→貼網頁→讀結果→再複製），不是自動攔截剪貼簿 |
| [clip.md](https://github.com/NorthIsUp/clip.md) | macOS 選單列背景程式，監看指定 App 複製的 HTML/RTF，貼到 code editor 時自動轉 Markdown | 自動化架構跟 NoMess 一樣，但清理規則太通用，**沒有針對終端機硬換行/CLI 符號**，且鎖定「貼到 code editor」 |
| [Paste-to-Markdown](https://github.com/doggy8088/Paste-to-Markdown) | HTML→Markdown 小工具 | 同上，非終端機導向 |
| Paste（pasteapp.io）、Maccy、PastePal、CleanClip 等 | 一般剪貼簿歷史管理工具 | 管理「歷史記錄」，不是「自動清理格式」 |
| [LessMess](https://apps.apple.com/ch/app/lessmess/id1459787403) | 名稱與概念接近，上架前要研究一下它實際做什麼、避免定位重疊 | 待查 |

**結論**：目前沒有人做到「背景自動攔截剪貼簿 + 專門辨識終端機輸出特徵 + 自動重排成乾淨格式，貼到任何地方都好看」這個組合——這是真正的空隙，值得做。

**命名備忘**：「Nomess Copenhagen」是既有居家收納消費品牌（非軟體），因為網域走 `nomess.noky.dev` 子網域，不會有衝突，不影響使用。

## 3. MVP 範圍（V0 只做這些，其他都不做）

**架構（三段式，之後每段都可獨立擴充）**

1. **監聽**：背景 Menu Bar App，監聽 `NSPasteboard.changeCount` 變化，偵測到新內容就攔截處理
2. **判斷 + 清理**：跑一組規則判斷「這段內容屬於哪種亂」，符合才清理，不符合就原樣放過（避免誤傷正常複製）
3. **寫回**：清理完的結果覆寫回剪貼簿，貼上時拿到的就是乾淨版本

**V0（第一版只做這個）**

- 只處理「終端機硬換行」這一種亂：偵測來源 App 是否為終端機類（Terminal / iTerm2 / Claude Code 執行環境），偵測內容是否有「短行 + 下一行非句子開頭」的硬換行特徵，重新接回成完整段落
- 一個開關：on/off，待在選單列，不做設定介面
- **不做**：表格對齊、CLI 符號清理、HTML 處理——全部列入 V1 backlog

**V1（V0 用順了之後再加）**

- 去除已知 CLI 介面符號（如 `⏺` `⎿`）
- 偵測並保留真正的程式碼區塊（用縮排/符號特徵判斷，不要把 code 也重排成一段文字）
- 「這次不要清理」快速鍵，避免誤判時卡住

**V2（如果真的常用、值得投資再做）**

- 第二種亂源：網頁 HTML 複製 → 乾淨 Markdown
- 規則可視化設定（哪些 App 要監聽、哪些規則開關）
- Windows 版
- **AI 公式貼上模組**（獨立功能，見第 4 節）——跟文字清理是不同的技術路線，不要混進 V0/V1

## 4. V2 候補功能：AI 公式貼上後維持漂亮（獨立評估過，先不做）

**目標**：AI 產出的數學公式複製後，貼到 Notion / Apple Notes / Messenger 等地方時維持可讀、好看的樣子。

**原理**：剪貼簿可同時放多種格式（純文字、HTML、RTF、圖片），貼上時目的地 App 自動挑它看得懂的格式。做法是複製時同時塞入「公式渲染後的圖片（PNG/SVG，用 KaTeX/MathJax 類引擎產生）」+「純文字備援（LaTeX 原始碼或 Unicode 近似符號）」。

**查證結果，依目的地拆開看**：

| 目的地 | 結果 |
|---|---|
| Notion | 預設不會自動把貼上的 LaTeX 原始碼變成公式區塊（已有多個獨立開源工具專門解這個痛點：`notion-latex-auto-paste`、`noeqtion`）。走「貼圖片」路線可行，會顯示成清晰截圖，但不是可編輯公式 |
| Apple Notes | 標準圖片貼上沒問題，會正常顯示 |
| Messenger | **最弱環節，且跟公式內容無關，是平台本身的限制**——有多篇論壇/GitHub issue 反映直接貼圖片進 Messenger 輸入框本身就常失敗或行為不一致（Mac、Android 都有），不是只有公式會這樣 |

**結論**：不能承諾「貼到哪裡都變漂亮」這種全有全無的目標。務實版本是：貼到支援圖片貼上的地方（Notion、Apple Notes、多數文件工具）公式變成清晰圖片；貼到純聊天工具（Messenger）退回成乾淨 Unicode 近似文字，而不是醜醜的原始 LaTeX 碼。這個功能技術路線跟文字清理完全不同（公式渲染引擎 vs. 文字重排規則），列為獨立模組，不混進 V0。

## 5. 技術風險提醒

1. **誤判比不處理更糟**——如果把本來正常的複製內容搞亂，使用者會立刻關掉不用。V0 規則要保守：寧可漏判不處理，不要亂改。
2. **隱私權限**——背景常駐監聽剪貼簿在 macOS 上會觸發權限提示（至少需要使用者明確允許），第一次設定要處理授權流程。
3. 不要一開始做成「規則引擎 + UI 設定」，那是 V2 的事——V0 先寫死規則，快速驗證「這個工具自己到底會不會每天開著用」。
4. 之後要上架：需要準備 Apple Developer 帳號、程式碼簽署（code signing）、公證（notarization）流程。
